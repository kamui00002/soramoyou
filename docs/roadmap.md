  - ~~露出ロック~~ → **完了（2026-09）**
  - ~~フォーカスロック~~ → **完了（2026-09）**
  - 空優先AE（白飛び防止）→ **完了（2026-09・ブランチ 機能-空優先AE・段階 A と同一ビルドで出荷）**
- 段階 B（連写→空基準で1枚選別・iOS 27・iPhone 16+）は判定ゲート（公開後4週間かつ新規投稿20件以上でphoto_source=cameraが20%未満なら着手しない）次第
  - **集計条件**: `post_completed` のうち `is_reedit=false`（＝新規投稿）に限定して `photo_source` の比率を出す。
    再編集・下書き再開は元がカメラでも `photo_source=library` になるため、混ぜるとカメラ比率を過小評価する。
  - ⚠️ **この計測窓には空優先AE（白飛び防止）が入っている**。段階 A 単体ではない。
    当初この解釈基準は「空優先AEがまだ無い」前提で書かれていたが、ユーザー判断で同一ビルド出荷としたため、
    測るのは「グリッド＋水平線ガイド＋空優先AE を載せた空カメラ」の転換率である。
    つまり**素の空カメラとの比較はもう取れない**。この行はその事実を残すために書いている。
  - **未達だったときの読み方（測る前に決めておく）**: ファネルのどこで落ちたかで解釈を分ける。
    `camera_opened` 自体が少ない → **導線が求められていない**（段階 B 不要）。
    `camera_opened` は出ているのに `camera_capture` へ落ちない → **撮る理由が足りない**。
    ただし差別化機能（空優先AE）は既に載っているので、「足りないから足す」ではなく
    **「差別化では動かない」という反証**として読む。構図ガイドだけでは弱いという外部調査の
    延長線上にあった仮説そのものが外れた、と結論してよい。
  - **空優先AEが効いていたかの確認（上の解釈の前提チェック）**: `camera_capture` の
    `sky_priority_enabled` / `sky_priority_measured` / `sky_priority_engaged` の 3 つを見る。
    `enabled=true` かつ `measured=false` が続くなら、それは**機能が動いていない**ということなので、
    上の「差別化では動かない」という結論を出してはいけない（測れていないものを反証に使わない）。
