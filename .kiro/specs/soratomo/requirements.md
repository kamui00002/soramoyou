# Requirements Document

## Project Description (Input)
そらもよう「そらとも」v1（グループ共有＋新着通知）。親しい友達だけの小さなグループで空の写真を共有する。
対象: ①グループ作成（名前→招待コード発行・共有シート） ②招待コードの手入力で参加 ③グループへ写真1枚の投稿（キャプション任意）とグループ別タイムライン（新しい順） ④新着投稿のプッシュ通知（タップでそのグループのタイムラインを開く。投稿位置までのスクロールは v1.1）。
対象外（v1）: リアクション・通報/ブロック・退出/削除・データ削除・URLスキーム/リンク参加・編集画面からの共有・複数グループ同時投稿・member_joined 通知。
公開前ゲート（本 spec では実装しないが、機能フラグを ON にする前に必須）: 退会時のグループデータ削除（審査 5.1.1(v)）／グループ投稿の通報・ブロック（審査 1.2）。実装は別 spec。
参照: ~/Downloads/そらもよう グループ共有 要件定義書.md の §5.2/5.3/5.4/5.5/5.7/7（数値・文言の既定値として）。§8.4 の storage.rules 本文・§9 の関数名・TypeScript 前提・fcmTokens サブコレクションは採用しない。§1.1 の feedbackId・要望本文は転記しない（repo 公開）。
現物の制約: Functions は JavaScript・Node 22・asia-northeast1。通知は既存 pushHelpers.js と users.fcmToken を使う。既存 onPostCreated（posts/{postId}）とは別名。iOS 16.0（ObservableObject）。URL スキーム無し。callable 未導入。
既存を壊さない: ルートの posts・既存通知・退会フローに影響を出さない。

## Introduction
「そらとも」は、親しい友達だけの小さなグループで空の写真を見せ合う機能です。グループを作ると招待コードが発行され、友達はそのコードを入力して参加します。メンバーが写真を1枚投稿すると、ほかのメンバーへプッシュ通知が届きます。通知を開くと、そのグループのタイムラインが表示されます。

本書はv1の要件を定めます。既存の公開SNS（ルートの`posts`・フォロー・いいね・コメント）とは別の閉じた共有の場として作り、既存機能の挙動は変えません。すべての入口を機能フラグで守り、公開前ゲート（要件17）がすべて完了するまで一般利用者にはONにしません。

本書は「何を満たすか」だけを定めます。コレクション名・関数名・Storageのパス・機能フラグの仕組みは設計フェーズで決めます。原案（要件定義書）で決まっておらず利用者の判断が必要だった事項は、2026-10-01に決まりました。決定の内容と反映先は、末尾の「決定事項（2026-10-01）」にまとめました。

### 用語とEARSの主語

| 用語 | 意味 |
|---|---|
| そらもようアプリ | iOSアプリ。端末側の振る舞いを定める要件の主語 |
| そらともバックエンド | FirestoreとStorageのセキュリティルール、およびCloud Functions。どちらで実現するかは設計で決める。サーバー側の要件の主語 |
| そらとも機能フラグ | そらともの入口を出すかどうかを利用者・ビルドごとに切り替える仕組み。仕組みは設計で決める |
| グループ | 招待コードで参加する、最大20人のメンバーの集まり |
| メンバー | グループに所属している利用者。オーナーを含む |
| オーナー | グループの作成者。v1のオーナー専用の操作は、招待コードの再発行（要件3）だけである |
| 招待コード | グループに参加するための8文字のコード。`XXXX-XXXX`の形で表示する |
| そらとも投稿 | グループに投稿された写真1枚と任意のキャプション |
| 公開前ゲート | 機能フラグを一般利用者にONにする前に完了が必須の作業（要件17） |

### 前提と制約（2026-10-01にmain 78feb91の現物で確認）

- Cloud FunctionsはJavaScript・Node 22で動き、リージョンは`asia-northeast1`である（`functions/index.js`の`setGlobalOptions`）。TypeScriptは使わない。
- プッシュ通知の送信には既存の`functions/pushHelpers.js`を使う。送信先のトークンは`users/{uid}.fcmToken`の1フィールドで、利用者ごとに1端末である。
- `exports.onPostCreated`（ルートの`posts/{postId}`・フォロワー向け通知）がすでに存在する。新しいトリガーには別の名前を付け、既存のトリガーは変更しない。
- Callable関数（`onCall`）はまだ1本も無い。
- ルートに`posts`コレクションがある。グループ配下に同じ名前のサブコレクションを作ると、コレクショングループのクエリ・インデックス・ルールで既存の`posts`と衝突しうる。名前は設計で決め、要件13で非干渉を求める。
- iOSアプリの最小対応バージョンは16.0で、状態管理は`ObservableObject`を使う。`.xcstrings`は無く、文言は日本語だけである。
- URLスキーム（`CFBundleURLTypes`）は無い。通知センターのデリゲートは`GoldenHourNotificationManager.shared`（`SoramoyouApp.swift`）で、プッシュ通知のタップでどこにも遷移していない。
- プッシュ通知の許可の要求と受信登録は`PushNotificationManager.requestAuthorizationAndRegister`が担う。ゴールデンアワー通知は`GoldenHourNotificationManager.enable`で別に許可を要求している。
- Remote Configは使っていない。
- 表示名とアイコンはFirestoreの`users`と`publicProfiles`にあり、Firebase Authのプロフィールには無い（`docs/pre-release-checklist.md`§2）。
- 会員登録画面（`SignUpView`）が尋ねるのはメールアドレスとパスワードだけである。そのため、表示名が空の利用者がいる。既存のプロフィール編集は表示名を50文字まで受け付け、`users`と`publicProfiles`へ保存する。
- 既存の通知設定は`users`の真偽値の項目で、項目が無い利用者には既定値を使う（`functions/index.js`の`PREF_DEFAULTS`）。既存の新着投稿通知は、受信者の`blockedUserIds`に投稿者が含まれていれば送らない（同ファイルの`isBlocked`）。
- 匿名ログインの処理（`AuthViewModel.signInAnonymously`）はあるが、画面から呼ぶ入口は無い。
- `reports`コレクションはあるが、通報を開発者へ届けるCloud Functionsは無い。
- 既存のフォロワー限定画像はログイン済みなら誰でも読める状態である。`storage.rules`のコメントには「StorageのルールからFirestoreは読めない」とある。メンバー判定を画像の読み取りにどう効かせるかは設計で現物を確かめる。ただし、グループの画像をメンバーだけが読める状態にすることは譲らない（要件11の1）。

## Requirements

### Requirement 1: 機能フラグと入口
**Objective:** 開発者として、そらともを機能フラグの内側で作り込みたい。これにより、公開前ゲートが揃うまでは一般利用者から隠したまま実機で検証できる。

#### Acceptance Criteria
1. **Where** そらとも機能フラグがOFFの利用者である場合、**the** そらもようアプリ **shall** そらともの入口・画面・通知の事前説明をいずれも表示しない。
2. **Where** そらとも機能フラグがONの利用者である場合、**the** そらもようアプリ **shall** ホーム画面に、グループ一覧を開くための「そらとも」ボタンを表示する。
3. **The** そらとも機能フラグ **shall** 一般利用者にはOFFのまま、開発者とテスト用アカウントに限ってONにできる。
4. **While** そらとも機能フラグがOFFである間、**the** そらもようアプリ **shall** 既存機能の表示と挙動をフラグ導入前と同じに保つ。
5. **While** 利用者が未ログイン（ゲスト閲覧中）である間、または匿名アカウントでログインしている間、**the** そらもようアプリ **shall** そらともの入口を表示しない。
6. **While** そらとも機能フラグがOFFの利用者である間、**the** そらともバックエンド **shall** その利用者からのそらともの読み取りと書き込みを拒否する。
7. **While** そらとも機能フラグがOFFの利用者である間、**the** そらともバックエンド **shall** その利用者へそらともの通知を送らない。

補足: 6と7は、アプリの入口を隠すだけではサーバーへの直接の要求を止められないために、多層防御として設けた。ルールとCloud Functionsは本番へ出した時点で、すべてのログイン利用者から要求を受ける。公開前ゲートG1が未完了のまま作られたデータは、退会で消せない。機能フラグの仕組みは設計で決める。先例は`skyMotionBeta`のカスタムクレーム（`firestore.rules`・`functions/skyMotion.js`）にある。

### Requirement 2: グループの作成
**Objective:** グループを作る人として、名前を付けてグループを作りたい。これにより、親しい友達だけの共有の場を用意できる。

#### Acceptance Criteria
1. **When** 利用者がグループ名を入力して作成を確定したとき、**the** そらもようアプリ **shall** グループを作成して招待コードの共有画面を表示する。
2. **The** そらもようアプリ **shall** 前後の空白を除いて1〜30文字のグループ名を受け付ける。
3. **If** グループ名が空白だけ、または30文字を超える場合、**the** そらもようアプリ **shall** グループを作らずに文字数の条件を伝える。
4. **The** そらともバックエンド **shall** グループの作成者を、そのグループのオーナーかつ最初のメンバーとして記録する。
5. **If** 利用者がすでに10個のグループに所属している状態で作成を確定した場合、**the** そらもようアプリ **shall** グループを作らずに「参加できるグループは10個までです」と表示する。
6. **If** 通信できない状態で作成を確定した場合、**the** そらもようアプリ **shall** グループを作らずに通信が必要であることを表示し、入力済みのグループ名を残す。
7. **While** グループの作成を処理している間、**the** そらもようアプリ **shall** 作成の操作を重ねて受け付けない。

### Requirement 3: 招待コードの発行と共有
**Objective:** グループのメンバーとして、招待コードを友達に送りたい。これにより、友達をグループに招ける。

#### Acceptance Criteria
1. **When** グループが作成されたとき、**the** そらともバックエンド **shall** 文字種`ABCDEFGHJKLMNPQRSTUVWXYZ23456789`（0・O・1・Iを除く）から8文字の招待コードを生成する。
2. **The** そらともバックエンド **shall** 招待コードを暗号論的に安全な乱数で生成し、有効なコードどうしが重複しないようにする。
3. **The** そらともバックエンド **shall** 招待コードに有効期限を設けない。
4. **The** そらもようアプリ **shall** 招待コードを4文字ごとにハイフンで区切った`XXXX-XXXX`の形で表示する。
5. **When** 利用者が招待の共有ボタンを押したとき、**the** そらもようアプリ **shall** 次の招待文を共有シートに渡す。

   ```text
   「{グループ名}」に招待されました。
   そらもようで空を共有しよう！
   招待コード: XXXX-XXXX
   アプリをお持ちでない方: {App StoreのURL}
   ```

6. **When** 利用者が招待コードのコピーボタンを押したとき、**the** そらもようアプリ **shall** 招待コードをクリップボードへコピーし、コピーしたことを表示する。
7. **The** そらもようアプリ **shall** メンバーであれば作成後もいつでも、タイムラインから招待コードの共有画面を開けるようにする。
8. **The** そらもようアプリ **shall** 招待コードの再発行の操作を、そのグループのオーナーにだけ表示する。
9. **When** オーナーが招待コードの再発行を確定したとき、**the** そらともバックエンド **shall** 1と2の規則で新しい招待コードを生成し、それまでの招待コードをその時点で無効にする。
10. **The** そらともバックエンド **shall** 招待コードの再発行を、そのグループのオーナーからの要求に限り受け付ける。
11. **When** 招待コードの再発行が完了したとき、**the** そらもようアプリ **shall** 新しい招待コードを招待コードの共有画面に表示する。
12. **If** 招待コードの再発行に失敗した場合（通信できない状態を含む）、**the** そらもようアプリ **shall** 表示中の招待コードを変えずに、再発行できなかったことを表示する。
13. **If** 再発行で無効になった招待コードで参加しようとした場合、**the** そらもようアプリ **shall** 要件4の5と同じく、エラーとして「招待コードが見つかりません」と表示する。

### Requirement 4: 招待コードでの参加
**Objective:** 招待された人として、受け取った招待コードを入力してグループに参加したい。これにより、友達の空を見たり自分の空を届けたりできる。

#### Acceptance Criteria
1. **The** そらもようアプリ **shall** 入力された招待コードを、英字の大文字と小文字の違い・ハイフン・空白を無視して照合する。
2. **The** そらもようアプリ **shall** 全角で入力された英数字・ハイフン・空白を、半角で入力されたものと同じに扱う。
3. **If** 正規化した入力が8文字でない場合、**the** そらもようアプリ **shall** サーバーへ問い合わせずに招待コードの形が違うことを伝える。
4. **When** 有効な招待コードでの参加が完了したとき、**the** そらもようアプリ **shall** 参加したグループのタイムラインを表示する。
5. **If** 招待コードに一致する有効なグループが無い場合、**the** そらもようアプリ **shall** エラーとして「招待コードが見つかりません」と表示する。
6. **If** 参加先のグループのメンバーがすでに20人いる場合、**the** そらもようアプリ **shall** 参加させずに「このグループは満員です（20人）」と表示する。
7. **If** 利用者がすでに10個のグループに所属している場合、**the** そらもようアプリ **shall** 参加させずに「参加できるグループは10個までです」と表示する。
8. **If** 利用者がすでにそのグループのメンバーである場合、**the** そらもようアプリ **shall** エラーにせず、そのグループのタイムラインを表示する。
9. **If** 通信できない状態で参加を確定した場合、**the** そらもようアプリ **shall** 参加させずに通信が必要であることを表示し、入力済みの招待コードを残す。
10. **While** 参加を処理している間、**the** そらもようアプリ **shall** 参加の操作を重ねて受け付けない。

### Requirement 5: グループ一覧
**Objective:** メンバーとして、自分が入っているグループを一覧で見たい。これにより、見たいグループのタイムラインへすぐ移動できる。

#### Acceptance Criteria
1. **When** 利用者がそらともの入口を開いたとき、**the** そらもようアプリ **shall** 自分が所属するグループの一覧を表示する。
2. **The** そらもようアプリ **shall** 一覧の各行にグループ名とメンバー数を表示する。
3. **The** そらもようアプリ **shall** 一覧を最新の投稿日時（投稿が無いグループは作成日時）が新しい順に並べる。
4. **When** 利用者が一覧のグループを選んだとき、**the** そらもようアプリ **shall** そのグループのタイムラインを表示する。
5. **The** そらもようアプリ **shall** 一覧画面に「グループを作る」と「招待コードで参加」の2つの操作を常に表示する。
6. **While** 所属するグループが1つも無い間、**the** そらもようアプリ **shall** グループが無いことと、作成または参加で始められることを表示する。

### Requirement 6: グループへの写真投稿
**Objective:** メンバーとして、撮った空の写真を1枚グループに投稿したい。これにより、友達に今日の空を届けられる。

#### Acceptance Criteria
1. **When** 利用者がタイムラインの投稿ボタンを押したとき、**the** そらもようアプリ **shall** 写真ライブラリから写真を1枚だけ選べる画面を表示する。
2. **When** 利用者が写真を選んだとき、**the** そらもようアプリ **shall** 選んだ写真のプレビューと任意入力のキャプション欄を表示する。
3. **The** そらもようアプリ **shall** キャプションを0〜100文字で受け付け、入力された改行を取り除く。
4. **If** キャプションが100文字を超えた場合、**the** そらもようアプリ **shall** 投稿を確定できない状態にし、上限を超えたことを示す。
5. **The** そらもようアプリ **shall** 投稿先を、開いているグループ1つだけにする。
6. **When** 利用者が投稿を確定したとき、**the** そらもようアプリ **shall** 画像のアップロードが完了してから投稿のデータを作成する。
7. **While** 投稿を送信している間、**the** そらもようアプリ **shall** 進み具合を表示し、投稿の操作を重ねて受け付けない。
8. **When** 投稿が完了したとき、**the** そらもようアプリ **shall** タイムラインに戻り、新しい投稿を先頭に表示する。
9. **If** 画像のアップロード後に投稿データの作成が失敗した場合、**the** そらもようアプリ **shall** アップロード済みの画像を削除してから失敗を表示する。
10. **If** 投稿が失敗した場合、**the** そらもようアプリ **shall** 選んだ写真と入力したキャプションを画面に残し、再試行の操作を表示する。
11. **If** 投稿中にアプリがバックグラウンドへ移った場合、**the** そらもようアプリ **shall** 投稿を完了させるか失敗として扱い、画像の無い投稿を残さない。
12. **If** 利用者が端末のタイムゾーンの同じ日に、そのグループへすでに20件投稿している状態で投稿を確定した場合、**the** そらもようアプリ **shall** 投稿せずに「1日に投稿できるのは1つのグループにつき20件までです」と表示し、選んだ写真と入力したキャプションを画面に残す。

補足: 12の件数の判定は、v1ではアプリ側だけで行う。サーバー側の判定はv1.1で加える。そのため、改造したアプリからの投稿は、この上限を超えうる。

### Requirement 7: 投稿画像の加工とプライバシー
**Objective:** 投稿する人として、写真に含まれる位置情報などを友達へ渡したくない。これにより、安心して空を共有できる。

#### Acceptance Criteria
1. **The** そらもようアプリ **shall** 投稿する写真を端末上で、長辺2048px以下の表示用画像と長辺512px以下のサムネイルに変換してから送る。
2. **The** そらもようアプリ **shall** 送る2種類の画像から、位置情報（GPS）を含むEXIFなどのメタデータを取り除く。
3. **The** そらもようアプリ **shall** 写真の向きを画素に反映し、メタデータが無くても正しい向きで表示されるようにする。
4. **The** そらもようアプリ **shall** 表示用画像を1.5MB以下、サムネイルを200KB以下のJPEGにする。
5. **If** 選んだ写真を読み込めない場合、**the** そらもようアプリ **shall** 投稿を始めずに、その写真を使えないことを伝える。

### Requirement 8: グループ別タイムライン
**Objective:** メンバーとして、グループに届いた空を新しい順に眺めたい。これにより、友達の今日の空をすぐに見られる。

#### Acceptance Criteria
1. **When** 利用者がグループを開いたとき、**the** そらもようアプリ **shall** そのグループの投稿を作成日時が新しい順に表示する。
2. **The** そらもようアプリ **shall** 最初に新しいほうから20件の投稿を表示する。
3. **When** 利用者がタイムラインの末尾に達したとき、**the** そらもようアプリ **shall** 続きの投稿を20件まで追加で表示する。
4. **The** そらもようアプリ **shall** 端末のタイムゾーンで投稿を日付ごとに区切り、見出しを「今日」「昨日」、それ以外は`M月d日`の形（例: 10月1日）とする。
5. **Where** 投稿の年が今年と違う場合、**the** そらもようアプリ **shall** 日付の見出しを`yyyy年M月d日`の形（例: 2025年12月31日）とする。
6. **The** そらもようアプリ **shall** 各投稿にサムネイル、投稿者の表示名とアイコン、投稿時刻、2行までのキャプションを表示する。
7. **The** そらもようアプリ **shall** 投稿者の表示名とアイコンをFirestoreのプロフィール情報から取得し、内部IDから作った文字で代用しない。
8. **If** 投稿者の表示名またはアイコンが未設定である場合、**the** そらもようアプリ **shall** 既存の画面と同じ規則の代替表示を使う。
9. **When** 利用者が投稿を選んだとき、**the** そらもようアプリ **shall** 表示用画像を拡大できる形で表示し、キャプションの全文を表示する。
10. **While** タイムラインを表示している間、**the** そらもようアプリ **shall** ほかのメンバーの新しい投稿を、手動で更新しなくても先頭に反映する。
11. **When** 利用者がタイムラインを引き下げて更新したとき、**the** そらもようアプリ **shall** 最新の20件を取り直して表示する。
12. **While** グループに投稿が1件も無い間、**the** そらもようアプリ **shall** 案内文「まだ投稿がありません。最初の空を共有しよう」と、投稿ボタン・招待ボタンを表示する。
13. **The** そらもようアプリ **shall** タイムラインにグループ名とメンバー数を表示する。
14. **The** そらもようアプリ **shall** グループの画像を、メンバー判定を経る取得経路で取得して表示し、メンバー判定を経ずに誰でも開ける恒久的なURLを保存しない。
15. **The** そらもようアプリ **shall** 投稿の削除の操作を、その投稿の投稿者本人にだけ表示する。
16. **When** 投稿者が自分の投稿の削除を選んだとき、**the** そらもようアプリ **shall** 削除してよいかの確認を表示する。
17. **When** 投稿者が削除の確認で削除を確定したとき、**the** そらもようアプリ **shall** その投稿のデータと、その投稿の表示用画像・サムネイルを削除する。
18. **While** タイムラインを表示している間、**the** そらもようアプリ **shall** 投稿者が削除した投稿を、手動で更新しなくても取り除く。
19. **If** 投稿データの削除に失敗した場合（通信できない状態を含む）、**the** そらもようアプリ **shall** 削除できなかったことを表示し、その投稿をタイムラインに残す。
20. **If** 投稿データの削除後に画像の削除に失敗した場合、**the** そらもようアプリ **shall** その投稿をタイムラインに戻さず、失敗を既存の非致命エラーの記録に残す。

### Requirement 9: 新着投稿のプッシュ通知の送信
**Objective:** メンバーとして、友達がグループに空を投稿したら通知で知りたい。これにより、アプリを開くきっかけが生まれる。

#### Acceptance Criteria
1. **When** グループに新しい投稿が作成されたとき、**the** そらともバックエンド **shall** 投稿者を除くそのグループのメンバーへプッシュ通知を送る。
2. **The** そらともバックエンド **shall** 通知のタイトルをグループ名にし、本文を「{投稿者の表示名}さんが空を投稿しました」にする。
3. **Where** 投稿にキャプションがある場合、**the** そらともバックエンド **shall** 本文の末尾に、キャプションの先頭30文字を「」で囲んで付ける。
4. **If** 同じ受信者へ同じグループの新着通知を直近5分以内に送っている場合、**the** そらともバックエンド **shall** その受信者には送らず、後からまとめて送ることもしない。
5. **The** そらともバックエンド **shall** 通知のスレッドIDと置き換えキー（`thread-id`と`apns-collapse-id`）をグループごとの値にし、通知センターでグループごとにまとめる。
6. **The** そらともバックエンド **shall** 通知のデータに、通知の種類（新着投稿）・グループID・投稿IDを含める。
7. **The** そらともバックエンド **shall** 既存の端末登録トークン（利用者ごとに1つ）を送信先に使い、複数の端末へは同時に送らない。
8. **If** 送信先のトークンが無効と判定された場合、**the** そらともバックエンド **shall** 既存の通知と同じ規則でそのトークンを削除する。
9. **If** 一部の受信者への送信が失敗した場合、**the** そらともバックエンド **shall** 残りの受信者への送信を続け、投稿そのものは取り消さない。
10. **The** そらともバックエンド **shall** 通常の通信状態では、投稿の作成から1分以内に通知を送り出す。
11. **The** そらともバックエンド **shall** 投稿1件ごとに、送った数と送らなかった数（間引き・トークン無し・送信失敗・通知設定OFF・ブロック・機能フラグOFFの別）をログに記録する。
12. **The** そらともバックエンド **shall** アプリのバッジ数を変更せず、通知音には既定の音を使う。
13. **If** 受信者がそらとも通知の設定をOFFにしている場合、**the** そらともバックエンド **shall** その受信者にはそらともの通知を送らない。
14. **The** そらともバックエンド **shall** 通知設定の「そらとも通知」がまだ保存されていない受信者を、ONとして扱う。
15. **If** 受信者の`users.blockedUserIds`に投稿者が含まれている場合、**the** そらともバックエンド **shall** 既存の通知と同じ規則で、その受信者にはそらともの通知を送らない。

### Requirement 10: 通知の許可とタップ時の遷移
**Objective:** メンバーとして、通知を受け取るかを納得して選び、通知を開いたらそのグループへ直接行きたい。これにより、届いた空をすぐに見られる。

#### Acceptance Criteria
1. **While** 端末の通知許可がまだ決まっていない間、**when** グループの作成または参加が完了したとき、**the** そらもようアプリ **shall** 通知の事前説明画面を1回だけ表示する。
2. **The** そらもようアプリ **shall** 事前説明画面に「友達が空を投稿したらお知らせします」という説明と、「通知を受け取る」「あとで」の2つの操作を表示する。
3. **When** 利用者が事前説明画面で「通知を受け取る」を選んだとき、**the** そらもようアプリ **shall** 既存の通知許可の仕組みを通してOSの許可ダイアログを表示する。
4. **When** 利用者が事前説明画面で「あとで」を選んだとき、**the** そらもようアプリ **shall** OSの許可ダイアログを表示せず、事前説明画面も再び表示しない。
5. **While** 端末の通知許可が拒否されている間、**when** グループの作成または参加が完了したとき、**the** そらもようアプリ **shall** 設定アプリで通知を許可する方法と、設定アプリを開く操作を1回だけ表示する。
6. **The** そらもようアプリ **shall** 通知許可の要求を既存の仕組みだけで行い、許可ダイアログを独自の経路で重ねて表示しない。
7. **When** 利用者がそらともの新着通知をタップしたとき、**the** そらもようアプリ **shall** その通知のグループのタイムラインを表示する。
8. **When** アプリが起動していない状態でそらともの新着通知がタップされたとき、**the** そらもようアプリ **shall** 起動後にその通知のグループのタイムラインを表示する。
9. **If** タップされた通知のグループに利用者が所属していない場合、**the** そらもようアプリ **shall** タイムラインを開かずにグループ一覧を表示し、開けなかったことを伝える。
10. **If** 通知のタップ時にそらとも機能フラグがOFFである場合、**the** そらもようアプリ **shall** そらともの画面を表示せず、通常どおりアプリを開く。
11. **If** 通知のタップ時に利用者が未ログインである場合、**the** そらもようアプリ **shall** そらともの画面を表示しない。
12. **The** そらもようアプリ **shall** 既存の通知（いいね・コメント・新着投稿・フォロー・おすすめ・ゴールデンアワー）のタップ時の挙動と計測を変えない。
13. **While** アプリが前面にある間、**the** そらもようアプリ **shall** そらともの通知を既存の通知と同じくバナーと音で表示し、通知センターにも残す。
14. **Where** そらとも機能フラグがONの利用者である場合、**the** そらもようアプリ **shall** 既存の通知設定に、そらともの通知をまとめてオンとオフにできる「そらとも通知」の設定を1つ表示する。
15. **The** そらもようアプリ **shall** 通知設定の「そらとも通知」を、既存の3種類の通知設定と同じ形（同じ画面・同じ保存の仕組み）で扱い、グループごとの切り替えは設けない。
16. **When** 利用者が「そらとも通知」を切り替えたとき、**the** そらもようアプリ **shall** その設定を、そらともバックエンドが送信の判定に使える形で保存する。
17. **The** そらもようアプリ **shall** 通知の事前説明と設定の文言で、グループごとに通知をオフにできるとは案内しない。

### Requirement 11: アクセス制御とデータ保護
**Objective:** メンバーとして、グループの写真をメンバー以外から見られない状態で共有したい。これにより、親しい友達だけへ安心して写真を見せられる。

#### Acceptance Criteria
1. **The** そらともバックエンド **shall** グループの情報・メンバー情報・投稿・画像を、そのグループのメンバーにだけ読ませる。
2. **If** メンバーでない利用者（未ログインを含む）がグループの情報・投稿・画像を読もうとした場合、**the** そらともバックエンド **shall** その要求を拒否する。
3. **The** そらともバックエンド **shall** 投稿の作成をそのグループのメンバーに限り、投稿者を要求した本人に限る。
4. **The** そらともバックエンド **shall** 投稿が参照する画像を、その投稿自身の保存場所の画像だけに限る。
5. **The** そらともバックエンド **shall** 画像の保存をメンバー本人の投稿用の保存場所に限り、表示用1.5MB以下・サムネイル200KB以下のJPEGだけを受け付ける。
6. **The** そらともバックエンド **shall** 投稿者本人に、自分の投稿のデータと、自分の投稿用に保存した画像の削除を許可する。
7. **The** そらともバックエンド **shall** 画像の削除の可否を、アップロード内容（種類・サイズ）の検査を含めずに判定する。
8. **The** そらともバックエンド **shall** メンバーの追加を有効な招待コードによる参加の経路だけに限り、メンバー一覧とメンバー数をクライアントから直接書き換えさせない。
9. **The** そらともバックエンド **shall** 招待コードの一覧取得と、所属していないグループの招待コードの読み取りを拒否する。
10. **The** そらともバックエンド **shall** 参加の要求が同時に届いても、メンバー数を20人以下、利用者の所属グループ数を10個以下に保つ。
11. **The** そらともバックエンド **shall** グループ名（1〜30文字）とキャプション（0〜100文字・改行なし）の条件をサーバー側でも検証する。
12. **The** そらともバックエンド **shall** 投稿の作成日時をサーバーの時刻で記録し、端末の時計で並び順を操作させない。
13. **The** そらともバックエンド **shall** メンバー判定を経ずに誰でも開ける恒久的な画像のURLを、投稿データとログに残さない。
14. **The** そらともバックエンド **shall** この要件と要件3の10の各項目について、許可される操作と拒否される操作の両方を自動テストで確かめられるようにする。
15. **The** そらともバックエンド **shall** 投稿のデータと画像の削除を、投稿者本人にだけ許可し、ほかのメンバー（グループのオーナーを含む）には許可しない。

補足: 7は、削除の要求にはアップロード内容が無いために設けた。作成・更新と同じ条件で判定すると削除が必ず拒否される（PR #141と同じ型の不具合）。v1でも、投稿に失敗したときの後始末（要件6の9）と、投稿者本人による投稿の削除（要件8の17）で削除を使う。

### Requirement 12: オフライン時と失敗時の振る舞い
**Objective:** メンバーとして、電波が弱い場所でも今どうなっているかを知りたい。これにより、投稿や参加が成功したかどうかで迷わずに済む。

#### Acceptance Criteria
1. **While** 端末がオフラインである間、**the** そらもようアプリ **shall** 以前に読み込んだタイムラインの投稿と画像を表示し、オフラインであることを示す。
2. **If** オフラインの状態でグループの作成・参加・投稿を確定した場合、**the** そらもようアプリ **shall** 処理を始めずに通信が必要であることを表示する。
3. **The** そらもようアプリ **shall** 失敗した投稿を下書きとして保存せず、通信が戻っても自動では送り直さない。
4. **If** 通信が途中で切れて投稿が失敗した場合、**the** そらもようアプリ **shall** 画像の無い投稿をサーバーに残さず、アップロード済みの画像の削除を試みる。
5. **The** そらもようアプリ **shall** 失敗の原因（通信・満員・上限・コードの不一致など）が分かる文言を表示し、内部のエラーコードをそのまま見せない。

### Requirement 13: 既存機能との非干渉
**Objective:** 既存の利用者として、そらともが加わっても今までの機能をそのまま使いたい。これにより、アップデート後も困らずに済む。

#### Acceptance Criteria
1. **The** そらともバックエンド **shall** そらとものデータを既存のルート`posts`コレクションとは別に保存し、既存の`posts`へのクエリ・インデックス・ルールの結果を変えない。
2. **The** そらもようアプリ **shall** そらとも投稿を、既存のホーム各フィード・ギャラリー・ランキング・検索・タグの画面に表示しない。
3. **The** そらもようアプリ **shall** そらとも投稿を、プロフィールの投稿一覧と投稿数・カレンダー・連続記録・図鑑・On This Day・ウィジェットに含めない。
4. **The** そらもようアプリ **shall** そらとも投稿を、お気に入りとおすすめの空へ追加させない。
5. **When** そらとも投稿が作成されたとき、**the** そらともバックエンド **shall** 既存の新着投稿通知（フォロワー向け・全員向け）を発火させない。
6. **The** そらともバックエンド **shall** 新しいトリガーに既存の`onPostCreated`とは別の名前を付け、既存のトリガーの対象と処理を変えない。
7. **The** そらともバックエンド **shall** 既存の3種類の通知設定（`notifyReactions`・`notifyNewPostsFromFollowing`・`notifyNewPostsFromEveryone`）とその既定値を変えない。
8. **The** そらともバックエンド **shall** 既存のコレクションとStorageのパスに対するアクセス条件を変えず、緩めない。
9. **When** そらともに参加・投稿した利用者が既存の退会処理を実行したとき、**the** そらもようアプリ **shall** 退会処理をエラーなく完了させる。
10. **The** そらもようアプリ **shall** 本specでは既存の退会処理の対象と順序を変えない。グループデータの削除は公開前ゲートG1で扱う。

### Requirement 14: 計測
**Objective:** 開発者として、そらともの使われ方を測りたい。これにより、継続率や招待の効果を判断できる。

#### Acceptance Criteria
1. **The** そらもようアプリ **shall** そらともの計測イベントを既存の計測窓口（`LoggingService.logEvent`）から送り、Firebase AnalyticsとPostHogの両方に記録する。
2. **The** そらもようアプリ **shall** イベント名とパラメータ名を、既存の命名に合わせて英小文字のスネークケースにする。
3. **The** そらもようアプリ **shall** 下表のイベントを、表の「記録する時点」ごとに1回ずつ記録する。
4. **The** そらもようアプリ **shall** イベントのパラメータに、グループ名・表示名・キャプション・招待コード・通知トークンを含めない。
5. **The** そらもようアプリ **shall** そらともの主要画面（グループ一覧・タイムライン・投稿・招待の共有・メンバー一覧・投稿詳細）を、既存の画面計測（`logScreen`）で日本語の画面名として記録する。メンバー一覧の画面名は「そらともメンバー一覧」、投稿詳細の画面名は「そらとも投稿詳細」とする。
6. **When** 利用者が「そらとも通知」の設定を切り替えたとき、**the** そらもようアプリ **shall** 既存の`push_pref_changed`イベントを、`pref`に`soratomo`、`enabled`に切り替え後の状態を入れて1回記録する。既存の3つの設定の`pref`の値は変えない。

| イベント | 記録する時点 | パラメータ |
|---|---|---|
| `soratomo_opened` | そらともの入口からグループ一覧を開いた | `group_count` |
| `soratomo_group_created` | グループの作成に成功した | なし |
| `soratomo_create_failed` | グループの作成に失敗した | `reason`（`user_limit`/`invalid_name`/`network`/`flag_off`/`unknown`） |
| `soratomo_invite_shared` | 招待の共有シートを開いた、またはコードをコピーした | `method`（`share_sheet`/`copy`） |
| `soratomo_group_joined` | 招待コードでの参加に成功した | `source`（v1は`code`のみ）、`already_member` |
| `soratomo_join_failed` | 参加に失敗した | `reason`（`invalid_format`/`not_found`/`group_full`/`user_limit`/`network`/`flag_off`/`unknown`） |
| `soratomo_post_created` | 投稿に成功した | `has_caption`、`duration_ms` |
| `soratomo_post_failed` | 投稿に失敗した | `stage`（`precheck`/`image`/`upload`/`save`）、`reason`（`offline`/`daily_limit`/`network`/`unreadable`/`too_large`/`permission`/`timeout`/`background`/`unknown`） |
| `soratomo_notification_prompt_result` | 通知の事前説明で操作を選んだ | `choice`（`allow`/`later`）、`granted` |
| `soratomo_notification_opened` | そらともの通知をタップした | `type`（`post_created`）、`result`（`opened`/`not_member`/`flag_off`/`signed_out`） |
| `soratomo_invite_code_regenerated` | 招待コードの再発行に成功した | なし |
| `soratomo_invite_regenerate_failed` | 招待コードの再発行に失敗した | `reason`（`not_owner`/`network`/`unknown`） |
| `soratomo_post_deleted` | 自分の投稿の削除に成功した | `image_cleanup`（`deleted`/`failed`） |
| `soratomo_post_delete_failed` | 自分の投稿の削除に失敗した | `reason`（`network`/`unknown`） |
| `soratomo_display_name_saved` | 表示名の事前入力で保存した | `trigger`（`create`/`join`） |
| `soratomo_display_name_failed` | 表示名の保存に失敗した | `reason`（`invalid_length`/`network`/`unknown`） |
| `soratomo_members_viewed` | メンバー一覧を開いた | `member_count` |

原案の成功指標（§1.4）は次のように測る。

- グループを作成または参加した利用者の割合は、`soratomo_group_created`と`soratomo_group_joined`で数える。
- 参加後7日の継続率は、上記イベントで作った集団と既存の起動・画面イベントを比べて出す。
- 通知の開封率は、`soratomo_notification_opened`の件数を、要件9の11でサーバーが記録した送信数で割って出す。
- 招待コード経由の参加数は、`soratomo_group_joined`で数える。

### Requirement 15: ログと個人情報
**Objective:** 利用者として、自分の名前や写真の説明をログへ残してほしくない。これにより、個人情報の流出を防げる。

#### Acceptance Criteria
1. **The** そらもようアプリ **shall** 端末のログとクラッシュ記録に、グループ名・表示名・キャプション・招待コード・通知トークンを出力しない。
2. **The** そらともバックエンド **shall** サーバーのログに、グループ名・表示名・キャプション・招待コード・通知トークンを出力しない。
3. **The** そらともバックエンド **shall** ログの中で、利用者・グループ・投稿を内部IDだけで識別する。
4. **If** そらともの処理が失敗した場合、**the** そらもようアプリ **shall** 既存の非致命エラーの記録に失敗を残し、アプリを落とさずに失敗を画面で伝える。

### Requirement 16: 性能とアクセシビリティ
**Objective:** メンバーとして、待たされずに空を共有し、VoiceOverでも使いたい。これにより、毎日気軽に開ける。

#### Acceptance Criteria
1. **When** 利用者がWi-Fi環境で12MP（1200万画素）の写真の投稿を確定したとき、**the** そらもようアプリ **shall** 10秒以内に投稿を完了する。
2. **The** そらもようアプリ **shall** タイムラインの最初の表示を、読み込み済みのデータがあれば1.5秒以内、無ければ3秒以内で終える。
3. **When** ほかのメンバーの投稿が完了したとき、**the** そらもようアプリ **shall** そのグループのタイムラインを表示中の端末へ、10秒以内に反映する。
4. **The** そらもようアプリ **shall** そらともの画面のすべてのボタンにVoiceOver用のラベルを付ける。
5. **The** そらもようアプリ **shall** 投稿画像のVoiceOver用の説明にキャプションを使い、キャプションが無ければ「{表示名}さんの空」とする。

### Requirement 17: 公開前ゲート
**Objective:** 開発者として、審査基準と利用者保護に必要な機能が揃うまでそらともを一般公開しないようにしたい。これにより、審査の却下と利用者の不利益を防げる。

#### Acceptance Criteria
1. **While** 下表の公開前ゲートのいずれかが未完了である間、**the** そらとも機能フラグ **shall** 一般利用者に対してOFFのままである。
2. **When** 一般利用者へのそらとも機能フラグをONに切り替えると判断するとき、**the** リリース手順 **shall** 下表のすべてのゲートの完了を確かめた記録を残す。
3. **The** 本spec **shall** G1とG2を実装しない。

| ID | ゲート | 根拠 | 実施する場所 |
|---|---|---|---|
| G1 | 退会時に、その利用者のそらともデータ（投稿・画像・所属情報）を削除する。既存の退会処理に組み込む | App Store審査ガイドライン5.1.1(v) | 別spec |
| G2 | グループ投稿の通報とブロック。通報を開発者へ届けて対応できる仕組みを含む（既存の`reports`には転送の仕組みが無い）。あわせて、初回の作成・参加の前にガイドラインの全文を表示して同意を記録することと、グループ名とキャプションを静的な語のリストで検査して該当すれば受け付けないこと（NGワードフィルタ）を含む | App Store審査ガイドライン1.2 | 別spec |

### Requirement 18: 表示名の事前入力
**Objective:** グループを作る人・参加する人として、友達に分かる名前でグループに表示されたい。これにより、タイムラインと通知で「誰の空か」が伝わる。

#### Acceptance Criteria
1. **While** 利用者のFirestoreのプロフィールの表示名が未設定または空白だけである間、**when** 利用者が「グループを作る」または「招待コードで参加」を選んだとき、**the** そらもようアプリ **shall** グループ名や招待コードの入力より先に、表示名の入力を求める。
2. **The** そらもようアプリ **shall** 前後の空白を除いて1〜20文字の表示名を受け付ける。
3. **If** 表示名が空白だけ、または20文字を超える場合、**the** そらもようアプリ **shall** 保存せずに文字数の条件を伝え、グループの作成・参加へ進ませない。
4. **When** 利用者が条件を満たす表示名を確定したとき、**the** そらもようアプリ **shall** その表示名を既存のプロフィール編集と同じ保存先（Firestoreの`users`と`publicProfiles`）へ保存し、そのあとで利用者が選んだグループの作成または参加の画面へ進む。
5. **If** 表示名の保存に失敗した場合（通信できない状態を含む）、**the** そらもようアプリ **shall** グループの作成・参加へ進ませずに、保存できなかったことを表示し、入力した表示名を残す。
6. **While** 利用者のプロフィールに表示名が設定されている間、**the** そらもようアプリ **shall** 表示名の入力を求めない。
7. **The** そらもようアプリ **shall** そらとも専用の別の表示名を持たず、ここで保存した表示名を、既存のプロフィールの表示名として扱う。

補足: 既存のプロフィール編集は、表示名を50文字まで受け付ける。1〜20文字の条件は、この要件で入力を求めるときだけに使い、すでに設定されている表示名は変えない。

### Requirement 19: メンバー一覧
**Objective:** メンバーとして、グループに誰がいるかを確かめたい。これにより、投稿する前に「誰が見るか」を知り、安心して空を共有できる。

#### Acceptance Criteria
1. **When** メンバーがタイムラインからメンバー一覧を開いたとき、**the** そらもようアプリ **shall** そのグループのメンバー全員の表示名とアイコンを一覧で表示する。
2. **The** そらもようアプリ **shall** 各メンバーの表示名とアイコンをFirestoreのプロフィール情報から取得し、未設定の場合は要件8の8と同じ規則の代替表示を使う。
3. **The** そらもようアプリ **shall** 一覧の中で、オーナーであるメンバーにオーナーであることを示す印を付ける。

## 対象外（v1）

- リアクション。
- 通報・ブロック・ガイドラインへの同意・NGワードの検査（公開前ゲートG2）。
- グループからの退出、グループの削除、メンバーの削除（投稿者本人による自分の投稿の削除は、要件8に含める）。
- 退会時のデータ削除（公開前ゲートG1）。
- URLスキーム・リンクからの参加。
- 編集画面からの共有。
- 複数グループへの同時投稿、複数枚の同時投稿。
- メンバーが参加したことの通知（`member_joined`）。
- 通知のタップで、その投稿の位置までスクロールすること（v1.1。通知のデータには投稿IDを含めておく）。
- 複数の端末への同時配信（既存のトークンが利用者ごとに1つのため）。
- 動画・コメント・公開グループ・グループ検索・通知への画像の添付・空タグ。
- 投稿詳細からの写真の端末への保存と外部への共有（v1.1）。
- そのグループのタイムラインを表示中は通知を出さない制御（v1.1。v1では要件10の13のとおり、既存の通知と同じく表示する）。
- 1日の投稿件数の上限（1人1グループにつき20件）のサーバー側の判定（v1.1。v1はアプリ側の判定だけ）。
- 180日を過ぎた投稿の自動削除と、削除前の予告（v1.1）。
- グループごとの通知のミュート（v1は「そらとも通知」のオンとオフだけ）。
- 匿名アカウントでのそらともの利用（入口を出さない）。
