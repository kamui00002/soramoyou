# Implementation Plan

## 進め方の約束

- 作業はmainから切ったブランチで行い、コミットは日本語にする（mainへの直接コミット・pushはしない）。
- 「（ユーザーのGOを取ってから実行）」と書いた操作（ルール・インデックス・Functionsのデプロイ、IAMの付与、クレーム付与の本番実行、push・PRの作成）は、GOを得るまで実行しない。
- firebase CLIには必ず `--project soramoyou-ios` を付ける（`.firebaserc` が空のため）。
- design.mdの「要確認」は、確かめるまで「検証済み」と書かない。ルールとトランザクションのテストは、わざと壊したもので期待外れになることを先に1回確かめてから通す（陽性対照）。
- iOSのビルドとテストは、シミュレータiPhone 17（553E8B23）以外で行う（別作業で使用中）。

  - クレームの無いアカウントで、次を確かめる。入口と「そらとも通知」の設定が出ないこと、CallableがフラグOFFの理由で拒否されること、そらともの通知が届かないこと、そらともの通知をタップしてもそらともの画面が出ないこと
  - 既存の通知（いいね・コメント・フォロー・ゴールデンアワー）のタップの挙動が変わらないことを確かめる。What's Newが未読のまま、そらともの通知でコールドスタートしたとき、What's Newがその起動か次の起動に1回出て既読になることも確かめる

  - 「そらとも通知」の切り替えが本番の利用者の文書に保存され、送信の判定に効くことを確かめる
  - ホーム・ギャラリー・プロフィールなどの既存の画面に、そらとも投稿が出ないことを目視で確かめる
  - そらともに参加・投稿したアカウントで、既存の退会処理がエラーなく終わることを確かめる
