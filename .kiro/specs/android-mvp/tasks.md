# Implementation Plan

## 前提と読み方
- 大きな並びは`requirements.md`のマイルストーン（M1→M6）の順とする。M1（ログインして本番フィードが読める・本番への書き込みゼロ）をタスク1〜11で完結させてから、M2以降へ進む
  - M1：タスク1〜11／M2：タスク12〜17／M3：タスク18〜19／M4：タスク20〜25／M5：タスク26〜33／M6：タスク34〜39
- 「（ユーザー作業）」「（ユーザー判断）」の付いたタスクは、ユーザー本人にしか行えない外部の作業・判断である。実装の担当は行わず、完了の報告を受けてから、それを前提とするタスクへ進む
- 書き込みの可否は、ビルドのマイルストーン設定で決まる。各マイルストーンで最初に書き込みが必要になるタスクで設定を上げ、結合タスクの最初で「そのマイルストーンの導線だけが現れること」を確かめる
- 「陽性対照」は、検出の仕組みが効いていることを、先に「失敗させて」確かめる手順である。陽性対照が取れなかった検証は、検証済みとして扱わない
- 本番での検証は、公開範囲「非公開」「フォロワーのみ」を基本にし、検証で作ったデータは検証後に削除する
- `(P)`は、明記した前提タスクが終わっていれば、同じマイルストーン内の他の`(P)`タスクと並行に進められることを示す

  - 陽性対照：メールアドレスや表示名などの契約外のキーを含むフィードバックと、2要素以上を一度に変えるブロックが違反になることを先に確かめる
