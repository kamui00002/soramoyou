# 実機ゲート: 空カメラ #116 / #117（TestFlight 1.12.0 / build 102）⭐️

作成: 2026-09-23（深夜）。**明日の日中に実機で確認する**ための手順。

## 何を確かめるのか

`build 102` は **#116（空優先AE = 白飛び防止）** と **#117（レンズ切替・フラッシュ・記録形式・48MP）** を載せた**検証用**ビルド。マージ判断はこの確認の結果で決める。審査中の 1.11.1 / build 101 とは別物（版数を分けてある）。

⚠️ 空優先AE は**明るい空**でしか意味のある判定ができない。曇天でも可だが、暗い時間帯は不可。

## 手順（アプリ内: 投稿 → 撮る）

### 1. 空優先AE が「空の側」を測っているか（本命）

構図: **画面の下半分に白い壁・明るい地面など / 上半分に空**。

- [ ] **縦持ち**で 1 枚撮る
- [ ] **横持ち（左回転）**で 1 枚撮る
- [ ] **横持ち（右回転）**で 1 枚撮る

期待: 3 枚とも `sky_meter_region="upper"` で、**下の白い面に引っ張られて暗くならない**。
❌ 暗くなったら、回転角と「空の側」の対応が逆（90°=左側 / 270°=右側の取り違え）。

### 2. 見上げたとき

- [ ] 真上の空を撮る → `sky_meter_region="whole_frame"`（傾きが求まらないので画面全体で測る）

### 3. 明るい空で白飛びが抑えられるか（較正の材料）

- [ ] 晴れた空（できれば太陽が入らない構図）で 1 枚
- [ ] 太陽が入る構図で 1 枚

期待: `sky_priority_engaged=true` になり、EXIF の露出補正がマイナスへ動く。
判断材料: `sky_max_peak_luma` が閾値に届かないのに見た目が飛んでいる → 閾値が高すぎ（250→245）。太陽入りで -2.0EV に張り付く → 許容率が低すぎ（2%→3〜5%）。曇天で灰色に落ちる → 許容率を上げる。

### 4. レンズ切替と 48MP（#117）

- [ ] 0.5x / 1x / 3x を切り替えて、それぞれ 1 枚ずつ撮る（切替時に固まらないか）
- [ ] 記録形式・解像度を **48MP** にして撮る → 撮れること・保存されること
- [ ] 48MP 中にレンズを切り替える（物理レンズを 1 本だけ掴む設計なので、ここが壊れやすい）

## 確認する場所（撮影後）

PostHog（プロジェクト Soramoyou / id 430627）で、`camera_capture` の下記プロパティを見る:

- `sky_meter_region`（`upper` / `whole_frame`）
- `sky_priority_engaged`、`sky_peak_luma`、`sky_max_peak_luma`、`luma_full_range`
- `camera_error` が 0 件であること

## 結果の反映先

- 合格 → #116 → #117 の順にマージ（#117 は #116 に積んである）。What's New 掲載の要否を判断（識別子 `2026-09-sky-ae`）
- 不合格 → どの向きで暗くなったかを記録して、回転角の対応を直す
