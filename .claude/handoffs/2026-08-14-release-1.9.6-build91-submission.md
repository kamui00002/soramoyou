## 🔴 build 92 で発覚した色バグ → build 93 で修正（2026-08-15）

### 実機検証の結果（build 92・投稿 `posts/E218A453-72B7-4612-961A-2F85E8B23059`）
- `skyType: sunset` ＝ 夕焼け写真に対して正しい値。
  - ⚠️ ただし**これは分類器が直った証拠にはならない**。修正前の 8/11 の投稿も `sunset` だった。
  - PR #79 が実証できたのは「`skyColors`/`colorTemperature` が**書かれるようになった**」こと（8/11-12 はフィールドごと不在、8/13 以降は存在）。
- `skyColors: ['#000000']` / `colorTemperature: 2021` ＝ **修正後も壊れたまま**だった。

### 真因（PR #79 と同じ型のバグが `ImageService.swift` に残っていた）
`CIAreaAverage` の出力は入力範囲によらず**常に原点(0,0)の1×1画像**。それを:
- `extractDominantColors`: 切り出し範囲に `cellRect`（原点が非ゼロ）を渡していた → 25セル中24セルが nil
- `calculateColorTemperature`: 切り出し範囲に `resizedCIImage.extent`（512×512）を渡していた → 範囲外の透明黒が混ざりほぼ真っ黒
- 真っ黒(r≈g≈b≈0)を色温度の式に入れると必ず約2020Kになる（計算で 2021 と一致を確認）

### 修正内容（commit `1eeee67`）
1. 上記2箇所の `from:` を `CGRect(x: 0, y: 0, width: 1, height: 1)` に（`SkyTypeClassifier.getAverageColor` と同じ）
2. **色温度の式の誤用も修正** — McCamy の式は CIE xy 色度座標を取るのに RGB をそのまま渡していた（x に r、y に b）。暖色で除数が負に振れ夕焼けが常に下限2000Kに張り付いていた。sRGB→線形RGB→XYZ(D65)→xy と変換してから渡すよう変更。
3. **主要色集計の非決定性も修正** — 25セルの平均色をそのままキーにすると全て count=1 になり `prefix(5)` が順序不定の任意5セルを返していた。32段階に量子化したキーで集計し、同数時はキー昇順で確定。
4. `extractColors` の未使用 CIImage / areaAverage フィルタを削除

### 検証（`scratchpad/verify_colors.swift` / `verify_cct.swift`・実投稿画像2枚）

|---|---|---|

| 曇り写真の平均色 | `#000000` → 2021K | `#98ABC0` → 9408K |
