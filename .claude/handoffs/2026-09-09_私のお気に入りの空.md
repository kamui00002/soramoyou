## 3. データ設計
```
users/{userId}/favorites/{postId}
  postId:    string   (= ドキュメントID。rules で一致を検証)
  createdAt: timestamp
```
- ページング cursor は **`createdAt` の Date**（`start(after: [Timestamp(date:)])`）。`DocumentSnapshot` を protocol に出さない＝テストでモック可能。
- 書き込みは **set/delete の明示指定**（`toggleLike` のようなサーバー側トグルにしない）。ローカル状態が古くても意図どおりに収束する（冪等）。

### 4-13. `firestore.rules`
`match /users/{userId} { ... allow delete: if isOwner(userId);` （156行）の直後・閉じ括弧の前にネスト:
```
      // ============================================
      // favorites サブコレクション（私のお気に入りの空）⭐️
      // ドキュメントID: {postId}。所有者だけが読める＝「自分だけのお気に入り」を構造で保証。
      // 一覧は order(by: createdAt) 1本なので複合インデックス不要。
      // ============================================
      match /favorites/{postId} {
        allow read: if isOwner(userId);
        // create/update とも許可: クライアントは set(冪等) で書くため、
        // ローカル状態が古く「既にある文書に set」しても update として通す必要がある
        allow create, update: if isOwner(userId)
                      && request.resource.data.keys().hasOnly(['postId', 'createdAt'])
                      && request.resource.data.keys().hasAll(['postId', 'createdAt'])
                      && request.resource.data.postId == postId
                      && request.resource.data.createdAt is timestamp;
        allow delete: if isOwner(userId);
      }
```
検証: `mcp__firebase__firebase_validate_security_rules(type: "firestore", source_file: "firestore.rules")`。
**デプロイは outward-facing → ユーザーの GO を取ってから**: `firebase deploy --only firestore:rules --project soramoyou-ios`（`.firebaserc` が空なので `--project` 必須）。**deploy 前にシミュレータで押すと permission denied でリバートする**（＝deploy 前に「動かない」と誤診しないこと）。
