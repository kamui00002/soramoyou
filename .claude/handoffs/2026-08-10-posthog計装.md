## ③ 編集エラーの error_context 細分化 = **完了（PR #77・オープン）**

ブランチ `改善-編集エラーのcontext細分化` / [PR #77](https://github.com/kamui00002/soramoyou/pull/77)（main から独立）。

**依頼の前提はズレていた（調査で確定）。** 依頼の「フィルタ適用 / 空マスク生成 / 書き出しの3分割」は**成立しない**。`generatePreview` の do ブロックで実際に throw するのは `imageService.generatePreview` の1箇所だけで、その先は `PreviewRenderer.renderPreview` に一本化されている（途中に catch できる境界が無い）。空マスク生成は `makeExportSkyMask` として既に分離済みだった。

**代わりに本当の分割ポイントは `PostViewModel.extractImageInfo` だった**（4つの抽出処理が1つの do/catch に同居）。実装したのは以下3点:

1. `extractImageInfo` の段階を context 接尾辞に（`.exif` / `.colors` / `.color_temperature` / `.sky_type`）
2. `generatePreview` の `try? await ensureSkyMaskCached` の握りつぶしをログ化（context `EditViewModel.generatePreview.skyMask`・継続する挙動は維持）
3. その skyMask ログの**重複ガード**（同一の画像インデックス＋変換状態につき1回）

⚠️ **3 は必須だった。** `ensureSkyMaskCached` は失敗時にキャッシュを nil のまま残すので、`generatePreview`（＝スライダー操作のたびに走る）が毎回再試行して毎回失敗する。ガード無しだとスライダー3往復で `error_occurred` 4件＋同数の Crashlytics 非致命的レコードが積まれた（ガードありで1件）。

⭐️ **成果**: 細分化した結果、謎だった「画像処理に失敗しました」の出所が **AI 空タイプ判定**（`extractImageInfo.sky_type`）だと即座に特定できた。

### ③で見つかった別タスク（この PR には含めていない）

- **A. AI 空タイプ判定は構造的に必ず失敗する** 🔴 — `SkyTypeClassifier.analyzeAverageHSV`（`SkyTypeClassifier.swift:348-356`）が `areaAverage` の出力（extent は常に `(0,0,1,1)`）を **crop 済み画像の extent**（`extractSkyRegion`・同 `170-181` が origin.y = 高さ×0.4 の矩形を返す）で `createCGImage` しようとして nil → `processingFailed`。**投稿の空タイプが自動で入っていない。** `ImageService.calculateColorTemperature` は同じ書き方だが origin が `(0,0)` なので成功する、という非対称。

## 計装をシミュレータで実証する手順（再利用可・重要）

`LoggingService` の `logger.info` は os_log なので、**`log show` の既定では拾えない**（info レベルは永続化されない）。`--info` が鍵。XcodeBuildMCP の runtimeLog / osLog ファイルには出てこないので、この直叩きが確実。

```bash
xcrun simctl spawn <UDID> log show --last 6m --info --debug \
  --predicate 'subsystem == "com.soramoyou"' --style compact | grep "Analytics event"
```

`grep -c` で回数を数えれば「ちょうど1回か」「出るべきでないものが0か」まで実証できる。

- シミュレータ UDID（今回使用）: `AC2D43EF-E998-4A2A-92AB-82DC08253925`（iPhone 17 Pro）
- UI 操作: XcodeBuildMCP の tap は**この環境では無効**。`mcp__Claude_Code_iOS_Simulator__control` の座標タップを使う（座標空間 402x874 / スクショは 919px 幅なので **係数 0.4374** で換算）
